# 人间牧场：UI精简、安全区与3D资产改版方案

日期：2026-10-30。状态：已实施卡牌底栏、三神原图、九技能徽章及Three.js占位场景；正式GLB美术和真机验收待后续。

## 1. 统一方向

世界采用参考图的手工微缩村庄3D：斜俯视、暖米黄墙体、陶土红/灰蓝屋顶、柔和草木、粗细明确的轮廓、哑光手绘质感与柔和阴影。UI采用复古神话卡牌与旧书印刷风：深墨底、象牙纸、细哑金边、玫瑰/灰蓝/灰紫区分三神。明亮世界承载玩法，深色少量UI保证识别，两者通过低饱和色与哑光质感统一。

三神人物使用用户定稿；场景参考只确定风格，不把整张参考图作为背景冒充3D。最新技能v02图优先于技能包内较早的试稿描述。图片中的旧游戏名、四技能、不同费用、3倍速、桥梁和区域标注文案均不自动成为需求；保留《人间牧场》的现有三神九技能、固定1倍速与浅滩规则。

依据：[项目UI技能](../skills/mythic-ui-assets/SKILL.md)、[三神方向](../skills/mythic-ui-assets/references/approved-gods-ui-direction.md)、[新版技能徽章](references/skill-icons-v02.png)、[UI构图](references/ui-composition-reference.jpg)、[3D村庄](references/3d-village-reference.png)。

## 2. 截图问题与布局修复

| 观察 | 当前实现原因/判断 | 改版方案 |
|---|---|---|
| 顶部计分被绿色开发提示压住 | 提示看起来由宿主叠加，当前源码未见此文案；计分固定顶中 | 为宿主提示预留独立禁放区，计分移入可用内容区；不要用z-index去盖平台提示 |
| 右上灵力和暂停被胶囊遮挡 | 页面仅部分使用设备safe-area，没有宿主胶囊避让 | 右上保留宿主区；暂停与菜单合并在左上，灵力移至底部技能栏 |
| 左上大标题占空间，靠边按钮风险高 | 局内重复品牌标题；截图红圈本身也遮住边界，不能仅凭图认定已经裁切 | 局内删除游戏标题与副标题，只留安全区内44—48 CSS px菜单/暂停入口 |
| 教程首屏看不到开始按钮 | `.dialog-card`整块滚动，`#dialogActions`跟在长正文后；标题正文占用过高 | 弹窗分为固定标题、可滚正文、固定底部按钮；初次提示压缩到目标+三步图示，进入按钮始终可见 |
| 两国大面板、天气文字、时间说明占据大量视野 | 多个常驻面板各自绝对定位，没有统一视野预算 | 国家详情默认收起；游戏年、固定倍率移入菜单/结算；正常天气不提示 |
| 气候选择、确认、详情、Toast可能互遮 | 各自固定位置；场景镜头不感知UI矩形 | 建立统一面板状态与占用区，气候面板替换技能详情区；同时只开一个详情面板；确认区预留固定位置 |

宿主类型尚不能只凭胶囊确定，不将截图当作已接入特定平台API的证明。后续实现单独的宿主适配层：浏览器获取viewport/visualViewport与CSS安全区；对应宿主有公开能力时再读取其安全区/胶囊矩形。没有接口时使用可配置的保守预留，不按截图分辨率硬编码位置。开发提示有/无、宿主胶囊有/无使用独立配置。

画布可以铺满背景，但所有可操作UI和重要目标都必须落在“可用内容区”。设备边缘、宿主禁放区、底部操作栏一起参与布局；使用CSS逻辑尺寸，不能把2796像素截图直接当CSS宽度。弹窗基于动态可用高度，不依赖单纯90vh。

## 3. 局内最小信息层

常驻只保留：暂停/菜单入口、灵魂计数、剩余时间、三神选择、当前神的三个技能、灵力余额。首次教学解释灵魂与灵力图标，常态用图标和数值。

建议横屏构图：

```text
┌────────── 宿主提示 / 刘海 / 胶囊预留区 ──────────┐
│ [暂停/菜单]             ✧ 123/300  03:26       │
│                                                │
│                 可交互3D双岛世界              │
│         岛名（总览显示）  异常时局部标记        │
│                                    [✓][×]     │
│ [三神小卡组]     [技能1] [技能2] [技能3]  ✦30  │
└────────────────底部安全区─────────────────────┘
```

空间不足时先去装饰、再压缩间距，最后调整排列；不把触控区缩小到难以点击。初步目标底部操作区约占可用高度20%—25%，关键交互目标位于其上方。小屏不照搬参考图中接近半屏高的完整立绘。

| 当前文字/元素 | 处理 |
|---|---|
| 局内“人间牧场 / 双岛纪事” | 删除，标题只在主页 |
| “第X年 / 固定1倍速·300秒” | 移入菜单和结算 |
| “选择神明与技能，干预这片人间” | 删除常驻；首次选择时短提示 |
| 两国人口、粮、居、天气常驻卡 | 点岛名/王宫才展开；缺粮/露宿/战争显示可定位小标记 |
| “风和日丽” | 删除；施加气候时显示小图标+倒计时 |
| 每个技能的名称与说明 | 小屏常态徽章+费用；选中时一行技能名，长按才看说明；宽屏可保留短名称 |
| 未解锁技能“XX解锁”长文字 | 锁标记；点按弹出解锁费用与确认 |
| 保存成功/操作成功频繁Toast | 保存使用短暂小标记；成功主要用场景效果、浮字和数字跳动；失败保留短原因 |
| 主界面英文长标题、三行介绍、技术说明、版本号 | 去掉英文和技术说明；版本移设置；保留游戏名、一句副题、开始/继续 |

首次教学：“5分钟收集300魂”+“选技能→点目标→施放”三步。继续深入的生育/生产策略放帮助页；第一次遇到相关操作再给短提示。已看教学本机记忆，重开不反复强制阅读。

## 4. 卡牌与技能如何落地

- 神明：采用用户三张定稿，缩成可辨识的半身卡面；选中卡略上移，其余露出头像与色带。完整立绘用于主页/详情，不挤占战场。
- 配色：生命视觉沿用爱神灰玫瑰/贝壳粉；天气烟蓝/冰青；死亡炭黑/灰紫。功能分组名称仍按现有策划，人物卡标签“爱神”等命名统一留待文案整理，不新增技能。
- 徽章：参考新版薄圈、纸墨笔触、清晰主形。九个技能分别表达实际行为，不能把“仁爱”图直接解释成当前不存在的新技能。
- 技能主体建议：和解=相向双手/橄榄枝；安居乐业=受庇护屋舍与麦穗；欢愉=贝壳心与双环；气候=日轮云层；闪电=旋云与冰青雷；陨石=下坠石与尾焰；暴怒=裂纹面具/燃烧怒目；瘟疫=染病叶与疫雾；亡灵=灰紫魂灯。
- 技能图、底座、边框、名称、费用与冷却独立分层。费用与中文由DOM渲染；选中用细描边，冷却用暗遮罩和读秒，锁定不改变图案主体。
- 先用已有参考定视觉样式，再制作缺失单体资产。参考拼板不直接当按钮图集，未经检查的原图不假定带透明通道。

## 5. 真3D占位与资产替换

建议保留现有模拟引擎，将Canvas 2D绘制替换为Three.js/WebGL场景层，DOM承担UI。斜俯视正交相机优先，固定方位、允许平移缩放；第一版不增加自由旋转，以免触控与选目标冲突。

占位阶段也使用实际mesh、材质、灯光、深度和拾取：房屋由墙体/坡屋顶/烟囱组成，树由树干和体块树冠组成，人物为有头躯四肢的简化模型，羊和野兽有可辨轮廓。可先程序生成模型，但通过同一个资产注册表供应，避免未来替换必须重写场景。

首批模型：双岛地块、海面、浅滩、火山；王宫、民居、粮仓、农田、羊栏、树石；居民、国王、士兵、羊、野兽、亡灵。人物用共用基础体+服色/头饰/武器区分，不在占位阶段过度雕刻脸部。

资产约定：

- 正式导入优先GLB；可保留DCC源文件在制作侧，运行包只包含优化资产。
- 注册表用稳定ID（如`building.house`、`actor.villager`），记录文件、缩放、朝向修正、包围盒、交互锚点、动画映射、低细节版本和占位回退。
- 世界空间约定Y向上、米为单位，模型地面中心为原点；角色约定面向+Z。导入器负责修正不同制作工具的单位/朝向。
- 现有逻辑平面(x,y)映射为3D(x,0,z)，逻辑距离与技能半径保持不变。屏幕点选通过射线落到地面/目标，不能沿用当前Canvas逆变换。
- 资产只表达实体状态。人口、技能、生命、碰撞/命中半径、路径与建筑占地由逻辑控制，替换外观不改变玩法数值。
- 动画语义：idle、walk、work、attack、hit、death；不是每个模型都强制具备，缺片段时使用明确回退。骨骼角色用独立动画实例，不能把普通静态实例化直接等同于骨骼动画批处理。
- 先将一栋房与一个居民替换为测试GLB，验证比例、朝向、动画和拾取后再批量换。缺文件或加载失败显示占位，不能中断对局。
- 草木/重复建筑共享几何与材质，适用时实例化；活动角色采用独立或专用批处理方案。纹理图集、远景LOD、少量动态阴影，避免每个角色单独高成本实时投影。资源与解码器随包部署，不依赖公网CDN。

Three.js官方依据：[正交相机](https://threejs.org/docs/pages/OrthographicCamera.html)、[glTF加载](https://threejs.org/manual/pages/load-gltf.html)。具体版本在实施时固定并记录。手机性能目标先按稳定30fps，60fps作为设备允许时的档位；包体/面数/纹理预算须以真机测量确定，当前不承诺任意资产直接流畅运行。

## 6. 遮挡处理不只针对UI

镜头依据可用游戏视野拟合双岛，而非屏幕几何中心。选中物被详情/底栏遮住时，镜头把目标带入可用区。人物被高建筑挡住时，选中轮廓/目标标记优先，必要时只淡化遮挡物，不把所有建筑全透明。神罚范围贴地显示，浮字向空闲方向偏移；特效不覆盖确认按钮。

详情/天气/解锁采用明确互斥状态；菜单与教学打开暂停。关闭后恢复进入前暂停状态。UI拦截触摸，不将点按钮/拖弹窗误传给世界。模拟、相机与HUD共享安全区结果，但数据职责分开。

## 7. 实施顺序与验收

1. **先修布局**：safe-area/宿主避让、弹窗固定按钮、局内文字精简；使用现有场景验证交互不丢失。
2. **统一UI皮肤**：三神卡、技能徽章、旧纸面板与细线边框；按实际手机显示尺寸确认，不照搬整张效果图。
3. **切真3D占位**：独立渲染层、正交相机、模型注册、射线拾取、地面技能圈、动态状态同步。
4. **资产替换演练与真机测量**：替换示例GLB，完整对局、存档、后台恢复、性能及宿主适配验收。

验收覆盖：16:9、19.5:9、20:9；低高度横屏；刘海/圆角；开发提示有无；胶囊有无；系统字体放大；主页、首次教程、国家详情、天气选择、瞄准、锁定技能、暂停与结算。先在CSS视口844×390、667×375、932×430与桌面模拟，再以用户同一测试容器真机核实。

硬性结果：开始/继续/关闭按钮无需滚动即可操作；关键数据不与平台控件相交；同一时间只有一处主要提示；按钮可触区域至少44 CSS px；地图仍能拖动缩放；技能点击不误穿透；更换模型不影响存档和计魂；低端机整局无明显卡死。UI标题用具有古典气质的中文字体，数据与小字优先可读，不为装饰牺牲清晰度。
