# 人间牧场 · H5 原型 v0.1

交付日期：2026-10-30。发布目标：TapTap H5。状态：本地可试玩，未上传、未提审、未上线。

## 产物与复现

- 源代码：项目根目录下 `game/`。
- 构建目录：`dist/`，入口 `dist/index.html`。
- 手动上传包：`release/renjianmuchang-h5-v0.1.0.zip`。
- 包体结构：`renjianmuchang/index.html` 与同目录 JS/CSS/图标/manifest；只包含一个英文顶层目录。ZIP 由本地脚本生成，已通过 Python zipfile CRC 检查。
- 构建：`npm run build`。预览：`npm run dev`，打开 `http://127.0.0.1:5173`。
- 游戏无外部 CDN、网络字体、广告或付费依赖；所有图形由 Canvas 绘制，短音效由 Web Audio 合成。无需安装 npm 依赖。
- 预览服务器只监听电脑回环地址；尚未开放局域网或公网。游戏需要 HTTP(S) 环境加载 ES Modules，不建议 file:// 双击启动。

## 已实现的核心循环

保持策划中的核心开局与技能数值：120名成年人、各480份粮食、各16栋房、农耕国16块田、畜牧国60只羊、各6只野兽、30灵力。固定1倍速，6秒一年，300秒期限，300魂胜利。

每名人类死亡只计一次灵魂与灵力；动物和亡灵不计魂。感染不提前计魂。结束判定按成功、灭绝、超时的顺序执行。两国分别进行出生、粮食消耗、劳动产出、建设与献粮检查。

九个技能均有可执行效果、费用和冷却。安居乐业、瘟疫和亡灵需要花费灵力解锁。提供生物范围瞄准、气候温度云量组合、陨石房屋伤害与火焰、疾病传播与免疫、尸体复苏、暴怒与简化军队行动。

UI包含主页、首次说明、双岛地图、神明卡、技能、国家详情、落点确认、暂停、失败/成功结算、重开和继续存档。触控使用Pointer Events；支持拖动、双指平移缩放，电脑支持滚轮。每30模拟秒与切后台时保存；恢复后暂停。manifest指定横屏，页面提供竖屏提示和全屏入口。

## 与完整策划的差异

这是明确缩减的玩法验证实现，以下内容不能按已完成验收：

1. **生产物流**：居民可见移动目前是自主漫游，田产按可用劳力汇总结算；尚未分配逐实体岗位、清兽清树开田路线及肉类搬运入库。宰羊完成后直接入库，野兽死亡直接产生粮食。建造/修理会检查劳力，但尚未占用具体工人。
2. **住房与伤害**：房屋耐久会影响容量，但尚无居民进屋状态；闪电目前可命中地图上的生物，陨石按范围伤害。未实现屋内避难和建筑倒塌时的逐住户伤害。
3. **战争**：已有实际居民动员、携粮、行军、作战、劫掠和返乡；路线、伤亡携粮丢弃拾取、劫掠烧屋、士兵单体停火后的独立结算尚未达到完整策划要求。
4. **灾害**：火山和火焰伤害已实现；尚无完整火势蔓延、树木可燃物与反击链。和平野兽目前不主动袭人。
5. **交互与表现**：尚无重叠对象目标列表、自动放大预览、屏外事件箭头、完整技能拖动边缘跟随和全套设置。动画与美术为程序绘制原型，不是最终精修素材；尚无背景音乐。
6. **数据维护**：未创建Excel数值工作簿，未实现JSON导入校验流程。当前常数保存在JS源文件中。
7. **平台能力**：未接TapTap账号、云存档、排行榜、广告。存档仅保存在当前浏览器与当前域名的localStorage中，清理浏览器数据会丢失；换域名不自动迁移。manifest不代表已经实现离线缓存或完整PWA安装能力。

## 验证记录

- `npm test`：9项测试全部通过。覆盖初始配置、暂停冻结、非法施法不扣费、死亡唯一计魂、亡灵不重复计魂及ID唯一、胜利判定优先级、病程计魂、存档恢复、冷却与气候计时、三组完整五分钟模拟。
- 空闲策略：种子11/22/33均正常超时，分别151/154/162魂，没有资源负值或非有限坐标。
- `node scripts/balance.mjs`：只使用合法技能调用的自动策略，种子11/22/33分别在278/281/277秒成功，303/301/313魂，剩余人口76/83/50。策略能精确扫描目标密度，不代表普通玩家已能稳定通关；仅用于证明当前简化经济下目标可达。未为了这些结果修改策划核心数值。
- 内置浏览器：验证横屏开局、气候施放扣费、陨石二次确认与实际收魂、暂停禁用施法、菜单保存、刷新恢复相同人口粮食灵魂和倒计时；竖屏显示旋转提示。观察时未发现浏览器错误日志。
- 真实Android/iOS设备、TapTap容器、低端机性能尚未验证。双指手势已实现但未在真机验收。

## TapTap 发布前下一步

先进行人工试玩与真机适配验收，按上方差异逐项决定补齐范围，再作为测试版本上传。需要选择正确的TapTap开发者与游戏条目，确认横屏设置，准备商店名称、简介、图标、截图及后台实际要求的材料；预览、提交审核与公开上线分开进行。

项目中的SVG图标只供网页与manifest使用，不能代替商店要求的PNG/JPG图标。当前截图仅为开发验证留档，不代表已满足TapTap商店物料尺寸要求。

后续使用已连接TapTap工具时，应先读取当前应用信息，再准备上传 `dist`，避免将原型提交到错误游戏。此版本没有进行任何远端上传或修改。
