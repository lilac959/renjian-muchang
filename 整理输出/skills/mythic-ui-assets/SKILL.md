# 神话 UI 素材

制作可用于游戏界面的边框、徽章、图标和装饰。核心视觉是古典装饰图形、清晰的扁平插画、旧纸与印墨质感。具体三个神的形象由用户另给图片，本技能不预设其身份、容貌、服饰、姿态或配色，不收录人物立绘规范。

## 使用边界

- 本技能记录参考方向，不代表用户已确认某一张试稿。用户当次指定的画风、色彩、形状和尺寸优先。
- 不固定顶部收魂栏、卡牌排列、技能数量、技能名称或费用；这些属于当前界面需求。制作单个素材时不擅自画整套界面。
- 不把不同参考的全部装饰叠在一起。每件素材选一个主体结构、一组纹样和一种主材质。
- 生图与光栅改图沿用可用的 imagegen 技能；已有可编辑矢量或界面元素优先沿用其制作方式。用户要求在 Figma 中编辑时使用相应 Figma 技能。不要只交付提示词代替用户要求的图片，也不要将整张截图称为可编辑 UI。

## 参考选择

先读 [参考索引](references/visual-reference.md)，再查看与当次素材有关的图片。图片用于理解轮廓、线条、配色关系和材质；其中原有文字、宗教符号与职业含义不自动成为游戏设定。

为《神明也疯狂》这组三神制作后续技能 UI 时，另读 [三神定稿的 UI 画风依据](references/approved-gods-ui-direction.md)，查看对应的用户定稿。该项目的定稿优先于早期通用徽章参考和已生成试作；这里只提炼 UI 配色与表现，不制定或修改人物设定。其他项目不自动套用这些配色。

## 共同视觉语言

- 形体以可辨认的外轮廓、大色块和少量内部线条为主。保留插画感，避免默认做成写实厚金属或现代玻璃按钮。
- 装饰可选细双线、拱形、局部卷草、植物枝叶、星芒、日月、飘带。装饰服务于结构和识别，不用密集花纹填满文字区。
- 质感可用轻微纸纤维、印刷颗粒、细小磨损、哑金墨色。纹理集中于底材和色块，不破坏图标轮廓与小字。旧纸不等于脏污破损。
- 颜色从当前参考和场景中提取。象牙纸色、墨黑或深蓝绿、古金可作为候选基底，玫瑰色、灰蓝或紫色可作局部强调；这些不是三神的固定颜色。用户要黑白灰时只保留明度和结构。
- 同组素材保持相近的线条粗细、边框层数、装饰密度、阴影方向和视觉重量。

## 边框素材

按用途选择结构，而不是所有面板共用一个缩放后的复杂画框：

- 卡牌框：纵向拱形或圆角长框；人物窗口、神名区与装饰边缘分开考虑。用户未给人物时交付空框，不补画神。
- 横向信息栏：中央可留数字徽章位，两端用少量对称装饰收尾。只有任务需要时才加入中央徽章，不强制每条栏都有。
- 说明面板：优先薄边、清楚的角部装饰、安静的正文底，避免用大面积花边挤压内容。
- 技能外框：圆形或任务指定轮廓，装饰层级比卡牌少，能容纳冷却、选中等状态。

空框要明确区分：框内透明、带底板、只有外部透明。数字、文字和内容窗口保留可用空间。长条需要适配不同宽度时，考虑端帽与中段分离或九宫格；仅在能验证边角不拉伸时称为可拉伸素材。

## 图标与徽章

- 优先借鉴参考中的“中央主体 + 环形底 + 少量外框”组织方式。飘带、放射纹和细花纹均可删减，不作为必需项。
- 中央主体表达技能行为或效果。先确认要表达什么，再选一个主符号，最多辅以少量辅助元素。不要因参考好看，就拿牛头、武器或骷髅随意对应治疗与和解。
- 图标主体、徽章底座、外框和文字标签尽量分层考虑。同组技能共享底座规则，中央符号彼此可区分。
- 把图标缩到实际使用尺寸看一次：主要轮廓要能识别，小细线不能糊成团。若尺寸未知，先按用途给出合理工作尺寸并说明，不固定所有素材都用同一像素大小。
- 技能名、费用、快捷键通常留给界面文字层；用户未要求时不把文字、英文职业名或数字烘焙进图标。
- 制作状态变体时保留主体一致，只用轮廓亮度、压暗、局部强调等表达状态。只有用户要状态套件时才扩展默认、悬停、选中、禁用或冷却状态。

## 制作与交付

1. 确定此次要交付的素材、数量、目标尺寸及透明区域；从已有对话获取信息，缺少关键输入再询问。
2. 为参考分配明确角色：结构、纹样、色彩、材质。按实际需要选图，不把所有参考都塞进同一次生成。
3. 生图描述包含用途、轮廓、主体含义、留空区、材质、配色及透明要求。成套素材共用外框规范，逐个修改主体。
4. 检查边缘裁切、透明通道、文本留白与缩小后的识别度。透明 PNG 必须是真实 alpha，不是棋盘格背景；准确像素尺寸以文件属性为准。
5. 项目素材保存到当前项目的合适输出目录，版本化命名。按任务交付单体 PNG、矢量或可编辑节点；预览拼板不能代替需要独立使用的素材文件。
6. 简短说明使用了哪些参考特征，以及哪些仍是占位。素材图不等于已接入引擎，也不等于已实现交互。
