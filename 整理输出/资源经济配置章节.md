### 二.3 资源经济配置方式

本章是从原文提取的**配置设计清单**，尚未生成或接入可运行的Excel／JSON配置。字段名是本次整理建议，便于后续落表，不代表新增玩法。原文已有数值直接沿用；原文未给数值的项目保持“待定”，不以0代替。

配置仍遵循原文的“Excel维护 → 校验 → JSON同步 → GameLogic读取”流程。沿用原有工作表，不另外增加经济货币、商店、价格或资源兑换机制。

| 内容类别 | 归属 | 配置边界 |
| --- | --- | --- |
| 玩法规则 | 玩法模块／GameLogic | 规定何时生产、何时入库、何时死亡、何时收费及胜负判定；修改数值不能绕过这些规则 |
| 资源经济参数 | 本模块配置表 | 初始资源、粮食产耗、住房容量、技能消耗、解锁与升级费用、生产及繁殖修正等 |
| 当前运行状态 | 存档 | 当前人口、库存、灵力、累计灵魂、剩余冷却等；不写回Excel |
| 玩家操作偏好 | 本地设置或存档 | 施放模式、振动等；沿用操作设置，不作为经济数值 |

配置表采用“功能 → 字段 → 类型／单位 → 原文值 → 生效条件 → 对应反馈”的结构。正文中的数值继续保留用于理解规则；实际配置按原文由Excel维护并同步JSON。

建议字段：`skill_id`、`level`、`cast_cost`、`cooldown_seconds`、`initially_available`、`unlock_cost`、`max_level`、`upgrade_cost`。基础信息放“技能基础”，等级信息放“技能等级”，保持每级一行。

**对应反馈与收费约束**：

- 施放成功：灵力“−X”浮字，冷却遮罩计时；解锁或升级成功：技能图标闪金光并显示对应Toast。
- 校验失败：不扣灵力、不进入冷却、不播放施法动画；灵力不足显示所需与当前数量。
- 放置落点、拖动准星、选择气候选项均不收费。
- 亡灵范围内无可用尸体时不收费。
- 闪电快速模式无目标、命中位置为房屋时不施放、不收费；两步模式确认空地则仍收费，并提示“闪电落空”。
- 已施放但无实际效果时不计默契；原文没有规定统一退款，不追加退款规则。

### 二.7 配置校验与玩法连接

| 配置影响的功能 | 必须保留的逻辑约束 | 对应检查与反馈 |
| --- | --- | --- |
| 粮食生产与入库 | 羊、野兽数量不等于粮食；宰羊或拾肉后才入库 | 国家卡库存与实际实体、入库事件一致 |
| 生育与住房 | 有空余住房且有余粮才正常出生；住房必须已完工 | 出生爱心、露宿帐篷、国家卡住房 |
| 劳力与效率 | 患病、享乐、暴怒居民不劳动；祝福不恢复其劳动能力 | 状态外观与实际劳力对应 |
| 灵魂结算 | 每个人类只计一次；受伤、感染不提前计魂，非人类及亡灵不计魂 | 实际死亡时灵魂+1，多人合并显示 |
| 灵力消费 | 校验在收费之前，保留技能各自的空放例外 | 成功扣费与冷却、失败原因提示 |
| 配置更新 | 检查ID、类型、单位、范围和引用，错误时保留上份有效配置 | 输出具体工作表、行和字段；检查通过后更新JSON |
| 配置生效 | 修改配置后重新开局生效；运行状态不写回Excel | 验证加载和表现一致，输出修改清单与未完成项 |
