## 编辑与接入

黄色单元格表示维护入口。参数表修改“策划基线值”；“当前代码值”保留作对照。技能基础的初始数据来自当前 `game/config.js`，解锁灵力为0表示初始可用。ID是本次提出的配置映射名称，不表示已有同名代码字段。

空白表示策划没有明确值或原型尚未实现，不能解释为0。概率存为0到1的数值；时间单位见每行。数值相同只表示常量相同，不代表完整条件和实体规则均已实现。界面短文本自动提取自代码单引号字符串，包含部分标签/片段；动态模板、HTML长文和完整交互说明仍需结合源码与“策划原表”维护。

本次只拆表，不改动玩法及平衡，不包含Excel导入器。后续接入需要：校验唯一ID、类型、单位、范围、引用及联动关系；输出修改差异；生成运行JSON并让逻辑/UI读取；重新开局验证。失败时保留上一份有效配置。空白保留旧值，删除需显式标记。运行人口、库存、剩余冷却及玩家偏好不写回本表。

## 已发现的接入差异

- `CONFIG.saveInterval`定义为30，但自动存档仍在`app.js`硬编码30秒；目标300和每年6秒也在UI及存档校验重复出现。
- 准星上移策划60px、原型40px；长按策划400ms、原型450ms；Toast策划2000ms、原型2800ms。
- 拾肉、运输入库、羊栏分流、清树、火势传播、王宫耐久及劫掠点火尚未实现。
- 房屋和农田建设仅按工人数检查，没有完整的独占劳动任务分配。修房按周期结算，并非累计实际劳动时间。
- 火山弹落点与策划的火山周围圆形范围不同；火山引火未检查雨雪禁燃，多处火焰伤害可能叠加。
- 参考图不能直接当作运行模型；待制作模型不填虚构文件路径。绘图坐标、装饰颜色和路径形状未逐一参数化。

需要程序行为才能实现的规则保留在约束列和策划原表，不把整段规则误当成只改一个数值就能生效的开关。
